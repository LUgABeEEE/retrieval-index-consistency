## 1. 要回答的问题

重分块 / 批量编辑之后，一批块的 `chunk_id` 改变、向量还没补（欠账）；生产每小时只有
**600 s 有界补嵌**窗口。问题：**同样 600 s，先补哪些块？不同调度策略的 recall@5 差多少？**

## 2. 场景（三套分开报，不混表）

- **A. 全量欠账（主场景，`full`）**：重分块后全部块身份改变，稠密臂为空。
  语料 `experiments/e2/corpus-structural.jsonl.gz`（131,028 块），向量
  `experiments/e2/vectors/vectors.npy`。词法索引已重建且覆盖全部块。
  `R_before` = 仅词法（dense 为空）的召回；`R_full` = 全量重建后的召回。
- **B. 需求驱动的编辑积压（次场景，`hot`）**：欠账页 = 事故前日志里历史查询 dense top-10
  命中过的页（每 rep 由该 rep 的历史半边确定；只用历史题，不看评测标签）。
- **C. 真实 24h 编辑欠账（诊断，`edit24`）**：`$KB_ROOT/state/manifest.json` 中
  语料快照时刻（2026-11-06 20:54:37 +08:00）前 24 h 有 mtime 的页；实测 895 页 / 9,404 块。
  用于展示「修索引不一定涨召回」的非单调性，**不参与主判据**。

所有场景的候选池 = 当前存活块集 ∩ 已嵌入集；块身份 = 语料行号，不存在 naive 陈旧行。

## 3. 预算 → 块数

- 吞吐取 E2 `vectors/meta.json` 的 `throughput_chunks_per_min`（294–299 块/分），缺失回退 296.5。
- 单块成本 c = 60 / 吞吐（常数，不含固定开销；Ollama batch=8 下保守）。
- `K(B) = floor(B / c)`；主档 600 s，敏感性 300/1200 s。

## 4. 六种策略（只决定欠账块里的先后）

1. **FIFO**：语料行序（页路径字典序 + 行号）＝重分块作业入队顺序。
2. **LRU**：页最近被访问优先；访问事件 = 事故前（全量索引）历史查询返回的 top-10 页，
   时间戳 = 历史集内随机排列位置（每 rep 重抽）。页内块序 = 历史证据次数降序，其次行号。
3. **FREQ**：页访问频次降序（同频按最近访问、再按行号）；页内块序同 LRU。
4. **RANDOM**：均匀随机排列（每 rep 一个种子）。
5. **GREEDY（子模贪心）**：`U(S)=Σ_{q∈H} Σ_{p∈gold(q)} sqrt(n_S(p)/N_p)`，
   边际增益 `W(p)·[sqrt((n+1)/N_p) − sqrt(n/N_p)]`（单调、边际递减、恒 > 0）。
   惰性贪心 + 堆；页内块序 = 历史证据次数降序，其次行号。
   只用历史半边的标注与日志，**不看评测半边标签**。
   这是论文 §4.2「ΔR 单调近似子模 + 单位成本边际增益」在可观测历史信号上的操作化。
6. **FULL（参照）**：全量重建（不是预算内策略）。**只叫"全量重建参照"，不叫上界**。

**控制（必做）**：`random`（同预算随机修复）同时度量"剪枝降噪"；`greedy-oracle`
（用全部 109 题标注算 W）是标注上界，只作参考、不参与判据。

## 5. 重复、切分与日志

- n=109（usable=1 且有 qrels）。每个 rep 把 109 题按 qid 随机二分为 `H_r`（54，历史）与
  `E_r`（55，评测），种子 `20261110 + r`，r=0…4。
- 策略只用 `H_r` 的日志/标注；`R_before/R_full/R_after` 只在 `E_r` 上算。
- 访问日志一律取**事故前**（全量索引）历史查询的 top-10 —— 事故期间日志会退化，用退化日志
  评价基线不公平；这一条在 v1 里写错了（用的是欠账状态日志），v1.1 改正，见 §9。
- 逐 rep 记录 Δrecall(pp) 与归一化恢复率；5 组配对观测。

## 6. 指标、统计与判据（captain 2026-11-10 批准）

- **主指标：绝对 recall@5 与 Δrecall(pp)**（相对该 rep 的 `R_before`）。
  同时给按题配对 bootstrap 的 95% CI。
- **归一化恢复率** `(R_after−R_before)/(R_full−R_before)` 只作附加列，且只在
  **分母 > 0 且 R_after ≤ R_full** 时给；否则写 `n/a` 并注明原因。
  理由：本语料上 recall@5 对稠密索引规模**非单调**（depth=50 截断 + clones/ 近重复页），
  部分修复的候选池更小反而可能涨召回；此时该比值不是比例，是公式失效的证据，不得当结果报。
- **统计**：按 rep 配对，**单尾 Wilcoxon signed-rank**（方向预注册：GREEDY > 基线），
  exact；n=5 时单尾最小 p=0.03125（双尾 0.0625），这是离散下限，不是事后换检验。
  同时报双尾 p、秩二列效应量、bootstrap 95% CI。
- **主判据**：600 s 上
  1. `mean_greedy(Δrecall_pp) − max_{基线}(mean_Δrecall_pp) ≥ 5 pp`；且
  2. GREEDY vs 该最佳基线的配对单尾 Wilcoxon `p < 0.05`。
  满足 → "调度有用"；否则 → 边界结论（调度收益依赖语料异质性 / 何时不该修）。
  300/1200 s 只作敏感性；方向不一致如实报告。**判据不再改动。**
- **n=5 的局限必须写进论文 §6.3**：exact Wilcoxon 的分辨率只有 0.03125，效应量比 p 值更可读；
  另外附 `--robust-reps 20`（额外切分，只 600 s）作为 p 分辨率的鲁棒性参考。

## 7. 实现口径

- 检索四步与 METRICS §3 一致：BM25(k1=1.2,b=0.75,depth=50) + 稠密内积(depth=50) +
  RRF(k=60，单位=块) + 页分数=页内块 RRF 最大值+0.002×min(命中块数,5)，取前 10。
- 页相关性 = 该页有块跨度 `[start, start+块内换行数]` 与 gold 窗口重叠；跨度从真实换行语料算，
  **不用 `chunks.tsv.gz`**。
- 稠密候选只来自已嵌入块；词法臂始终覆盖全语料（词法索引不含向量）。
- 融合键 = 语料行号；一次评测只改变已嵌入集合。
- 预算内不重算全库：预计算 `S = Q·Vᵀ`（136×N，float32）与 BM25 top-50，评测只做掩码+top-50。
